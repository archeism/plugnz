# OMP and Cursor native agent registration

Date: 2026-10-22. Repository base: `2795dee`. Research only: no implementation, installation, paid-provider run, native runtime qualification, or GitHub mutation. Scope: choose registration and identify the smallest qualification slice. Research/machine-local/RSI/factory skills loaded; skills unchanged. CodeGraph exploration preceded local source inspection. Acceptance: each proposed route follows its owning source; unresolved semantics stay explicit.

## Decision

Choose the **existing native package routes** as implementation candidates: OMP extension-package `agents/*.md`, Cursor plugin `agents/*.md`. Neither requires a new agent runtime or standalone user-agent fanout. **Do not admit portable agents yet.** Source reading establishes discovery routes, not end-to-end parity. In particular, both hosts can override a requested model under native policy; strict unavailable-model error behavior in the current portable contract is not established.

Existing native proofs concern other capabilities, not agents. See `docs/hosts/omp.md` and `docs/evidence/omp-native-extension-package-20261013.json`.

## Cursor

Plugnz already stages `.cursor-plugin/plugin.json` and native plugin content into `~/.cursor/plugins/local/<name>` (`src/hosts/cursor-writer.ts:126`, `docs/hosts/cursor.md`). Both its managed and directory profiles mark agents `unverified` (writer lines 372/404). Cursor 2.4.0 is a current managed lifecycle baseline, not proof of present-day agent behavior.

The official [plugin reference](https://cursor.com/docs/reference/plugins#agents-format) documents plugin-root `agents/*.md` with YAML name/description and Markdown prompt. Its agent table does not establish model parsing. The official [subagent guide](https://cursor.com/docs/subagents#model-configuration), retrieved 2026-10-22, documents specific model IDs, parent inheritance by default, and inherited parent tools including MCP. It also documents model substitution under team restrictions, unavailable plan models, and legacy non-Max plans. Thus omit tools and unresolved model fields; do not promise that any mapped model necessarily executes or fails closed. These live docs are unversioned and are not a Cursor 2.4 qualification.

The repository already pins [cursor/plugins@eb4db2b55b2b7dec3d9282754cddf0a56bf4ff10](https://github.com/cursor/plugins/tree/eb4db2b55b2b7dec3d9282754cddf0a56bf4ff10) in `confer.yaml`. Its `scripts/generate-pstack-harness-trees.mjs:18–20,110–113` states Cursor consumes `pstack/` directly and carries canonical agents into generated trees. This is packaging precedent, not proof of plugin-subagent model parsing or invocation.

**Next proof:** on one recorded Cursor version/surface, install an isolated native plugin fixture and show its agent appears in actual native delegation, executes the preserved instructions, exposes the normal native tools, and records the selected model. Prove plugin-level model parsing (not just `.cursor/agents` parsing), omitted-model selection, collision identity, reload, changed-byte update, and removal. Record explicit-model failure/substitution behavior and account/plan restrictions. Editor, CLI, and cloud qualification remain separate. Do not substitute copied-file evidence for native execution or run providers during this planning task.

Proposed five-file qualification slice: `test/cursor-native-agents.test.ts` (new opt-in probe), `test/fixtures/portable-agents-cursor/agents/reviewer.md`, `test/fixtures/portable-agents-cursor/plugnz.agents.json`, `test/fixtures/portable-agents-cursor/plugin.json`, `docs/evidence/cursor-native-agents.md`. After proof, production conversion can fit `src/hosts/cursor-agents.ts` (new), `src/hosts/cursor-writer.ts` (stage call and profile), and focused existing lifecycle tests.

## Shared acceptance constraints

Keep explicit destination model > user alias > package alias > omitted; no model guessing, cross-target mapping, generated `inherit`, tool preferences, or new agent runtime. Existing common portable validation/resolution and immutable source capture stay authoritative. A documentation decision can select the routes now, but the capability flags remain closed until native qualification resolves the semantic gaps. No skill revision or runtime-success claim follows from this research.
